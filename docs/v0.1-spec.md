# AU Invoice Check - v0.1 Product Contract

## Product goal

Provide deterministic Australian tax-invoice checks for AI agents and automated accounts-payable workflows.

The product should help an agent answer:

- Is the required tax-invoice information present?
- Does the GST arithmetic make sense?
- Does the supplier ABN validate?
- Can the supplier ABN be verified against the Australian Business Register?
- Is the supplier registered for GST?
- Does the invoice require buyer identity information?
- Are there findings that require human review?

## Target user

Developers and businesses building:

- accounts-payable automation
- supplier onboarding
- invoice processing
- finance agents
- Australian compliance workflows

## v0.1 MCP tools

### validate_tax_invoice

Checks whether the supplied structured invoice data contains the core information required for an Australian tax invoice.

### check_invoice_gst

Checks invoice totals and GST arithmetic for supported standard GST scenarios.

### verify_invoice_supplier

Checks the supplier ABN and available Australian Business Register information.

### assess_tax_invoice

Runs the supported invoice, GST and supplier checks and returns one structured assessment.

## Result language

Use deterministic findings such as:

- meets_core_requirements
- missing_required_information
- gst_math_mismatch
- supplier_verified
- supplier_not_found
- gst_registration_mismatch
- needs_review

Do NOT return conclusions such as:

- legally compliant
- illegal
- ATO approved
- guaranteed compliant

# v0.1 Tool Contract

## Shared invoice input

The invoice-checking tools use structured JSON input.

Supported v0.1 shape:

```json
{
  "supplier": {
    "name": "Example Pty Ltd",
    "abn": "51 824 753 556"
  },
  "buyer": {
    "name": "Buyer Pty Ltd",
    "abn": "12 345 678 901"
  },
  "issue_date": "2026-10-14",
  "document_intent": "tax_invoice",
  "currency": "AUD",
  "items": [
    {
      "description": "Consulting services",
      "quantity": 1,
      "line_total": 1500.00,
      "taxable": true
    }
  ],
  "subtotal": 1500.00,
  "gst": 150.00,
  "total": 1650.00,
  "gst_included": false
}
```

## Shared input rules

### supplier

Required:

- supplier.name
- supplier.abn

### buyer

buyer.name and buyer.abn are optional for invoices under $1,000 including GST.

For invoices of $1,000 or more including GST, at least one of:

- buyer.name
- buyer.abn

must be present.

### issue_date

Required.

Format:

```text
YYYY-MM-DD
```

### document_intent

Required in v0.1.

Supported value:

```text
tax_invoice
```

This represents that the document clearly indicates it is intended to be a tax invoice.

### currency

Optional.

Default:

```text
AUD
```

v0.1 only assesses AUD invoices.

### items

At least one item is required.

Each item must contain:

- description
- line_total
- taxable

quantity is optional where not applicable.

### monetary fields

Required:

- subtotal
- gst
- total

Values must be zero or positive numbers.

### monetary conventions

For v0.1:

- `subtotal` means the amount before GST.
- `gst` means the GST amount supplied on the invoice.
- `total` means the total amount including GST.
- when `gst_included` is `false`, item `line_total` values are treated as GST-exclusive.
- when `gst_included` is `true`, item `line_total` values are treated as GST-inclusive.
- v0.1 supports fully taxable or wholly GST-free supplies for GST arithmetic, but does not support invoices containing a mixture of taxable and GST-free supplies.
- `check_invoice_gst` requires `gst_included` to determine whether item line totals are GST-inclusive or GST-exclusive.

# Tool 1: validate_tax_invoice

## Purpose

Check whether the structured invoice contains the core information required for an ordinary Australian tax invoice within the supported v0.1 scope.

## Input

Uses the shared invoice input.

## Checks

The tool checks:

- document is identified as a tax invoice
- supplier identity is present
- supplier ABN is present
- issue date is present
- at least one supplied item is described
- item pricing is present
- GST amount or GST treatment can be determined
- taxable status of supplied items can be determined
- buyer identity or ABN is present when total is $1,000 or more including GST

## Output example

```json
{
  "schema_version": "0.1",
  "tool": "validate_tax_invoice",
  "result": "meets_core_requirements",
  "threshold": {
    "total_including_gst": 1650.00,
    "buyer_identity_required": true
  },
  "findings": []
}
```

## Possible result values

```text
meets_core_requirements
missing_required_information
needs_review
unsupported_scenario
```

# Tool 2: check_invoice_gst

## Purpose

Check GST arithmetic for supported standard GST scenarios.

## Input

Uses the shared invoice input.

## Supported v0.1 GST scenarios

v0.1 supports:

- fully taxable standard GST sales
- invoices containing GST-exclusive subtotal plus GST plus total
- invoices where GST is exactly consistent with the standard Australian GST rate
- rounding tolerance of one cent where arithmetic requires rounding

v0.1 does not attempt to determine special GST treatment.

## Checks

The tool checks:

- supplied line totals reconcile to the stated subtotal for supported GST-exclusive invoices
- supplied line totals reconcile to the stated total where applicable for supported GST-inclusive invoices

```text
subtotal + gst = total
```

For fully taxable standard GST-exclusive amounts:

```text
gst ≈ subtotal × 10%
```

For GST-inclusive amounts where applicable:

```text
gst ≈ total ÷ 11
```

## Output example

```json
{
  "schema_version": "0.1",
  "tool": "check_invoice_gst",
  "result": "gst_math_valid",
  "calculated": {
    "expected_gst": 150.00,
    "expected_total": 1650.00
  },
  "supplied": {
    "subtotal": 1500.00,
    "gst": 150.00,
    "total": 1650.00
  },
  "findings": []
}
```

## Possible result values

```text
gst_math_valid
gst_math_mismatch
needs_review
unsupported_scenario
```

# Tool 3: verify_invoice_supplier

## Purpose

Verify the supplier ABN using AU Business Identity and the Australian Business Register.

## Input

```json
{
  "supplier_name": "Example Pty Ltd",
  "supplier_abn": "51 824 753 556"
}
```

## Checks

The tool checks:

- ABN format
- ABN checksum
- ABN registry presence
- ABN status
- available registry GST registration status
- supplied name against available registry entity/business names

Name matching in v0.1 is deterministic only.

The tool may normalise:

- letter case
- whitespace
- punctuation

A non-match does not mean the supplier is invalid.

A non-match produces:

```text
result → needs_review
finding → SUPPLIER_NAME_MISMATCH
```

The tool must not infer fraud, illegality or supplier invalidity from a name mismatch alone.

## Output example

```json
{
  "schema_version": "0.1",
  "tool": "verify_invoice_supplier",
  "result": "supplier_verified",
  "supplier": {
    "abn": "51824753556",
    "checksum_valid": true,
    "registry_found": true,
    "status": "Active",
    "gst_registered": true,
    "name_match": true
  },
  "findings": []
}
```

## Possible result values

```text
supplier_verified
supplier_not_found
supplier_inactive
needs_review
registry_verification_unavailable
```

# Safety and scope rules

The tools must not claim:

```text
legally compliant
ATO approved
guaranteed compliant
illegal
fraudulent
```

The tools assess supported invoice information and deterministic checks only.

Complex or unsupported cases must return:

```text
needs_review
```

or:

```text
unsupported_scenario
```

rather than guessing.

# v0.1 Architecture Rule

AU Invoice Check must not duplicate the ABR integration.

Supplier registry verification must reuse the existing AU Business Identity verification service or shared business-identity logic.

The invoice product owns:

- invoice rules
- GST arithmetic
- consolidated findings

AU Business Identity owns:

- ABN validation
- ABR registry verification
- registry data normalisation
