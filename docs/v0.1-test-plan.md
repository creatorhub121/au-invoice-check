# AU Invoice Check — v0.1 Contract Stress Test

## Purpose

Test the product contract before application code is written.

The contract passes only if the expected result for each scenario is clear and deterministic.

---

## Case 1 — Valid invoice under $1,000, no buyer identity

Input:

```json
{
  "supplier": {
    "name": "Australian Taxation Office",
    "abn": "51 824 753 556"
  },
  "buyer": {},
  "issue_date": "2026-10-14",
  "document_intent": "tax_invoice",
  "currency": "AUD",
  "items": [
    {
      "description": "Professional services",
      "quantity": 1,
      "line_total": 500.00,
      "taxable": true
    }
  ],
  "subtotal": 500.00,
  "gst": 50.00,
  "total": 550.00,
  "gst_included": false
}
```

Expected:

```text
validate_tax_invoice → meets_core_requirements
check_invoice_gst → gst_math_valid
buyer_identity_required → false
```

## Case 10 — Supplier exists but supplied name does not match registry name

Input:

```json
{
  "supplier_name": "Completely Different Business Name",
  "supplier_abn": "51 824 753 556"
}
```

Expected:

```text

```

The tool must NOT claim:

```text

```

## Case 11 — Supplier found but not GST registered while GST is charged

Registry result:

```text
registry_found → true
status → Active
gst_registered → false
```

Invoice:

```text
gst > 0
```

Expected:

```text
result → needs_review
finding → SUPPLIER_NOT_GST_REGISTERED
```

The tool should flag the inconsistency for review without making a legal or fraud conclusion.

v0.1 uses the GST registration information available from the registry response and does not claim to reconstruct historical GST registration status for every invoice date.

## Case 12 — Registry verification unavailable

# PASS criteria

The contract passes the design stage only if:

```text
1. Every supported case has one deterministic result.

2. Unsupported cases are explicitly rejected instead of guessed.

3. Registry failure does not prevent local invoice checks.

4. Invalid ABNs are rejected before registry lookup.

5. The $1,000 buyer-identity threshold behaves correctly at the boundary.

6. GST calculations tolerate normal one-cent rounding only.

7. Supplier-name mismatch produces review, not a fraud/legal conclusion.

8. No tool claims ATO approval or legal compliance.
```
